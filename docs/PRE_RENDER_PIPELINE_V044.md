# Pre-render Pipeline v0.44

Status: draft pipeline for deterministic structure before final visuals.

## Goal

The project needs a middle layer between simulation data and cinematic images.
This layer should make every important battle/interface fact visible and
checkable before a styled render is generated.

The pipeline is:

```text
campaign input
-> v0.44 runtime
-> logs / calculations / state
-> screen payload
-> render contract
-> pre-render structure
-> final visual artifact
-> artifact manifest
```

## Why this exists

Final images are allowed to be beautiful, dramatic, and stylized. They are not
allowed to mutate the run.

The pre-render catches:

- wrong HP numbers;
- invented kills;
- missing enemies;
- wrong hero positions;
- wrong round/action labels;
- reward drift;
- continuity drift;
- UI text that does not match the source screen payload.

## Pre-render artifact types

### 1. Screen structure JSON

Machine-checkable layout manifest.

```json
{
  "screen_id": "campaign01_v044_battle_round_02",
  "stage": "battle_v09_round",
  "source_payload": "game-data/screen-payloads/campaign01_v044_screen_payloads.json",
  "layout": {
    "zones": ["header", "tactical_map", "action_log", "unit_roster", "footer"]
  },
  "facts": [],
  "warnings": []
}
```

### 2. Tactical map SVG/PNG

Deterministic tactical structure for hex/board screens.

Should include:

- field bounds;
- blocked/objective/extraction cells;
- hero markers;
- enemy markers;
- status markers;
- round/action labels;
- HP labels if available.

### 3. UI panel manifest

Exact text and values that must appear on a generated interface screen.

Should include:

- panel title;
- exact labels;
- exact numeric values;
- source `log_refs` and `calculation_refs`;
- priority for visual hierarchy.

### 4. Cinematic prompt packet

A prompt-ready package for image generation. It may add mood and composition,
but must carry all locked facts from the render contract.

```text
artifacts/
```

Large final PNGs may stay outside Git and be referenced through a manifest.
Small JSON/SVG pre-render artifacts may be kept in Git when useful for review.

## Tooling direction

First useful tool:

```text
tools/render_screen_structure.py
```

Responsibilities:

1. Read `game-data/screen-payloads/campaign01_v044_screen_payloads.json`.
2. Select one `screen_id` or render all screens.
3. Validate required render contract fields.
4. Emit pre-render JSON.
5. For tactical screens, optionally emit SVG.

Non-goals for the first tool:

- no cinematic image generation;
- no broad engine rewrite;
- no v0.40 payload takeover;
- no balance changes.

## First target screens

Prioritize screens where factual drift would be most damaging:

1. `battle_v09_round` screens.
2. `tactical_encounter_start`.
3. `run_summary`.
4. `progression`.
5. `campaign_continuity`.

Hero selection, briefing, and mood screens can follow after battle/report screens
are stable.

## Review workflow

For each rendered slide/screen:

1. Inspect screen payload.
2. Inspect render contract.
3. Generate pre-render structure.
4. Compare labels and positions against payload.
5. Generate final visual.
6. Compare final visual against pre-render.
7. Store artifact references in a manifest.
