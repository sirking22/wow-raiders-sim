# STRATEGIC MAP — пошаговый детерминированный стратегический слой (v0.7)

Стратегическая карта теперь **просчитывается ходами**, по тому же контракту, что и боевой движок:
семя RNG → детерминированный ход → лог 1:1 с ходами → кадры (ходы+1) → результат → render-contract → валидатор.

Движок: `engine/strategic_v07.py`. Геометрия: `engine/hexgrid.py`. Тесты: `tests/test_strategic_v07.py` (**8/8 PASS**).

## Регион «Сумеречные руины»

- Гекс-карта **8×6**, odd-r.
- Террейн и стоимость входа: `road=1, plains=2, forest=3, hazard=4, mountain=непроходим`.
- Старт отряда: `c1r5`. Цель: `c3r0` — «Алтарь сумерек» (`ruined_obelisk_court`).
- POI: `Тайник разведчиков` (c5r4), `Разрушенный алтарик` (c4r2).
- Враг: `Сумеречный дозор` (c3r2) → при контакте хэндофф в тактический бой `enc_005_v07`.
- Таймер вражеского ритуала: `required_turns=7` (создаёт давление «успеть до завершения»).

## Что считается за один ход — `resolve_turn(intent)`

1. **RNG хода**: `random.Random(f"{seed}:{turn}")` — детерминированно и воспроизводимо.
2. **Намерение** (`intent`): `advance_objective` | `move_to {target}` | `claim_poi {poi}`.
3. **Движение**: `shortest_path` по enter_cost террейна, отряд проходит в пределах `SQUAD_MOVE=6`.
4. **Туман войны**: `hexes_in_range(pos, SIGHT=2)` раскрывает новые гексы.
5. **Контакт с врагом**: если отряд на враге или рядом — событие `encounter_triggered` с `battle_seed` (хэндофф в тактику; стратегия НЕ выдумывает исход боя).
6. **POI**: захват при попадании на гекс.
7. **Таймер ритуала**: +1 за ход; при достижении `required` — `ritual_complete`.
8. **Цель/терминальное состояние**: `objective_reached_in_time` / `objective_reached_too_late` / `ritual_won_by_enemies`.
9. Запись лога хода + снапшот-кадр.

## Артефакты (game-data/strategic/)

| Файл | Содержимое |
|---|---|
| `strat-twilight-001-log.json` | по одной записи на ход (intent, move{path,cost}, events, revealed, threat) |
| `strat-twilight-001-frames.json` | снапшот на каждый ход + начальный (len == ходы+1) |
| `strat-twilight-001-result.json` | итог: состояние, ритуал, угроза, стычки, POI, post_battle_options, gm_questions, validation_errors |
| `strat-twilight-001-render-contract.json` | контракт рендера гекс-карты (must_show / must_not_invent) |

## Валидатор приёмки `validate(sm)`

- `len(log) == turns`, `len(frames) == turns + 1`.
- Все гексы пути в границах поля; каждый шаг пути — реальный сосед предыдущего.
- Нет выдуманных актёров/POI в событиях (только известные id).
- Прогон канона: `validation_errors == []`.

## Render-contract (что должен показывать экран стратегии)

Показать: токен отряда на `squad_hex`, маркер цели, раскрытые гексы vs туман, вовлечённых врагов, полосу угрозы, прогресс ритуала `N/required`.
Нельзя выдумывать: гексы вне `8×6`, актёров вне кадра, позицию отряда, отличную от `squad_hex` кадра.
Экран отвечает на 5 вопросов: где мы / что произошло / кто в каком состоянии / какие риски выросли / что делать дальше.

## Связь тактики и стратегии (две петли)

```
стратегический ход → контакт с врагом → encounter_triggered{battle_seed}
        ↓                                              ↓
  следующий стратегический ход  ←  результат тактического боя (post-battle loop v0.7)
```

Стратегия и тактика — один детерминированный контракт; обе петли просчитываются ходами и обе рендерятся из снапшотов.
